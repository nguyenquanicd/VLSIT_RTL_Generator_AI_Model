# Phase 6 · Specification Document — /spec_pdf_generator

**Mục tiêu:** Sau khi Gate 5 đã ký, tổng hợp toàn bộ thông tin từ các gate artifact và RTL
để tạo tài liệu specification hoàn chỉnh theo chuẩn IP documentation.

**Điều kiện:** `schemas/verification_report.json` phải có `gate_5_approved: true`.

**Output:** `docs/specification.md` (Markdown) + `docs/specification.pdf` (nếu pandoc có sẵn).

---

## Quy tắc bắt buộc

1. Mọi thông tin kỹ thuật (parameter, port, register) phải lấy từ artifact — không tự suy diễn.
2. Verification section phải lấy số liệu thực từ `verification_report.json` và `rtm.json`.
3. Synthesis section phải lấy số liệu thực từ `synth_report.json` (nếu có).
4. Nếu một section không có đủ dữ liệu → ghi `TBD` rõ ràng, không bịa.
5. Không viết comment kiểu "generated by Claude" vào document.

---

## Bước 1 — Pre-flight

Đọc và kiểm tra theo thứ tự:

```
schemas/verification_report.json  → gate_5_approved == true
schemas/final_config.json         → parameters, IP name
schemas/rtm.json                  → requirements, assertions, sign-off status
schemas/selected_testplan.json    → TC list, coverage
schemas/synth_report.json         → area, cell count (nếu có)
schemas/structured_spec.json      → REQ list, description (nếu có)
src/rtl/filelist.f                → module list
```

Nếu `gate_5_approved != true` → dừng: _"Gate 5 chưa ký. Chạy `/verification` trước."_

Tạo thư mục `docs/` nếu chưa có.

Thông báo:
```
Pre-flight OK:
  IP: <ip_name>   Rev: <spec_revision>
  Gate 5: approved ✓
  Modules: <N>  |  SVA: <N>  |  TC: <N>  |  REQ: <N>
  Synth report: <có / không có>
```

---

## Bước 2 — Lấy thông tin từ artifact

Trích xuất và lưu vào biến nội bộ:

**Từ `final_config.json`:**
- `IP_NAME` — tên IP
- `SPEC_REV` — revision spec
- Danh sách parameter (tên, giá trị, mô tả)
- Feature matrix (F01–FXX enabled/disabled)

**Từ `src/rtl/filelist.f`:**
- Danh sách module (tên file → tên module)
- Module hierarchy từ top-module

**Từ RTL source (đọc port list của top module):**
- Tất cả port: tên, direction (input/output), width, mô tả

**Từ `rtm.json`:**
- Danh sách REQ-ID với status (signed_off / locked)
- Assertion list với file SVA tương ứng
- Mutation scores

**Từ `verification_report.json`:**
- Sim summary (total TC, pass, fail)
- Mutation summary
- Sign-off count

**Từ `synth_report.json` (nếu có):**
- Total cells, chip area, flop count
- Clock frequency / timing

## Bước 4 — PDF conversion (nếu có tool)

```bash
# Thử pandoc trước
which pandoc && pandoc docs/specification.md \
    --from markdown \
    --to pdf \
    --pdf-engine=weasyprint \
    -o docs/specification.pdf \
    && echo "PDF OK"

# Nếu không có pandoc: thử weasyprint trực tiếp
which weasyprint && python3 -c "
import markdown, weasyprint
html = markdown.markdown(open('docs/specification.md').read(), extensions=['tables','toc'])
weasyprint.HTML(string=html).write_pdf('docs/specification.pdf')
print('PDF OK (weasyprint)')
" 2>/dev/null

# Nếu không có tool PDF → chỉ giữ Markdown
echo "Markdown output: docs/specification.md"
echo "(Dùng VSCode / Typora / GitHub để xem hoặc export PDF)"
```

## Xử lý lỗi

| Tình huống | Hành động |
|------------|-----------|
| `gate_5_approved != true` | Dừng, chỉ rõ cần chạy `/verification` trước |
| `synth_report.json` thiếu | Bỏ qua Chapter 08, ghi `TBD` |
| `structured_spec.json` thiếu | Dùng REQ-IDs từ `rtm.json` thay thế |
| Port list không đọc được từ RTL | Ghi `TBD — lấy từ src/rtl/<top>.sv` |
| Cả pandoc lẫn weasyprint đều thiếu | Chỉ output Markdown, hướng dẫn cách convert |
| `docs/specification.md` đã tồn tại | Hỏi "Ghi đè? (yes/no)" trước khi overwrite |
